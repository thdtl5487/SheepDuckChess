너는 VS Code에서 작업하는 시니어 풀스택 엔지니어다. 저장소는 SheepDuckChess이며 구조는 backend(TypeScript, Express, ws, typeorm)와 frontend(React, TS, Recoil, CRA)로 구성되어 있다. 현재 게임 서버는 WebSocket으로 JOIN_GAME, TURN_MOVE, TURN_RESULT, OPPONENT_DISCONNECTED, OPPONENT_RECONNECTED, GAME_OVER를 주고받는다. 프론트는 matchInfo를 localStorage에 저장하고 /game/:gameId로 진입한다. 목표는 “접속 끊김 유예시간(기본 60초)을 두고, 다른 디바이스로 로그인해도 진행중인 게임을 이어서 할 수 있게” 만드는 것이다.

요구사항:

유예시간을 .env로 설정한다.

DISCONNECT_GRACE_SECONDS=60 (없으면 60으로 기본값)
.env는 .env에서 읽힌다.
게임 진행 중인 유저가 접속이 끊기면:

게임 서버는 해당 유저의 disconnectAt(timestamp)를 기록한다.
상대에게 OPPONENT_DISCONNECTED를 보낸다(기존 동작 유지).
유예시간이 지나면 서버가 자동으로 GAME_OVER를 확정한다.
끊긴 유저가 white면 black 승, black이면 white 승.
GAME_OVER 메시지를 양쪽(연결된 쪽)에게 브로드캐스트하고,
API/DB에도 게임 결과를 기록할 준비를 한다(최소 구현이면 메모리만으로도 가능하지만, 크로스 디바이스 복구를 위해 아래 4번과 연동).
유예시간 내에 끊긴 유저가 재접속(JOIN_GAME)하면:

서버는 유예 타이머를 취소한다.
상대에게 OPPONENT_RECONNECTED를 보낸다(기존 동작 유지).
재접속한 소켓에게 현재 게임 상태(TURN_RESULT에 board/turn/logs/lastMove 등)를 즉시 다시 보내서 화면을 복구한다(현재 ChessSession.bindSocket()이 비슷한 동작을 이미 한다면 그 흐름을 유지/보강).
“같은 계정이 다른 디바이스로 재접속”도 동일하게 처리한다.
크로스 디바이스(폰→PC)에서 gameId를 찾을 수 있도록 API를 추가한다:

API 서버에 GET /api/active-game (또는 POST여도 됨) 엔드포인트를 만든다.
인증은 기존 RF 토큰 기반 유저 조회(getUserInfoByRFToken 사용 패턴)로 한다.
응답: 유저가 참여 중이고 ongoing인 게임이 있으면
gameId
yourColor (가능하면)
graceSeconds (env값)
secondsRemaining (disconnectAt 기반 계산, 연결 중이면 null 또는 graceSeconds)
status ("ongoing" | "grace" 등)
진행 중 게임이 없으면 null을 반환.
프론트 UI: 로그인 후(또는 메인/로비 진입 시) 진행중 게임이 있으면 팝업을 띄운다.

문구: “현재 게임 진행중입니다. 계속할까요? (nn초 뒤 자동 기권)”
버튼 2개:
“계속하기” → /game/:gameId로 이동 (기존 진입 로직 재사용)
“나가기/기권” → 서버에 기권 요청(가능하면 WS 메시지나 API) 또는 그냥 닫기(최소 구현이면 닫기만 해도 됨. 단, 유예시간 지나면 서버가 자동패 처리)
UI는 기존 스타일(Tailwind/기존 컴포넌트)로 최소한만 추가한다. 새 페이지/복잡한 모달 라이브러리 추가 금지.
세션 삭제 정책을 수정한다:

현재 game-server는 소켓 0개면 세션을 즉시 삭제하거나 cleanup에서 삭제한다.
이 동작을 “유예시간 동안은 삭제 금지”로 바꿔라.
즉, 둘 다 끊겨도 disconnectAt이 최근이면 세션을 유지하고,
유예가 끝나 GAME_OVER 처리 후 일정 시간(예: 1~5분) 뒤 cleanup 가능.
최소 구현은 메모리 유지로 하고, DB 영속화는 옵션으로 둔다.
보안/검증(최소):

JOIN_GAME 시 유저가 그 gameId의 참가자인지 검증(최소라도)한다.
잘못된 userId/gameId로 붙으면 ERROR 반환.
구현 힌트/현재 코드 참고:

game-server: index.ts, ChessSession.ts, SessionManager.ts
frontend: MainPage.tsx, GamePage.tsx, 매칭 훅 useMatchSocket.ts
프론트는 이미 OPPONENT_DISCONNECTED/RECONNECTED를 처리하고, WS 재연결도 일부 구현되어 있다.
작업 방식:

먼저 관련 파일들을 읽고 현재 흐름을 요약한 뒤, 필요한 최소 변경 설계를 제시한다.
그 다음 코드를 직접 수정한다(필요하면 파일 추가 가능).
변경 후 서버 실행이 깨지지 않게 타입 에러/런타임 에러를 점검한다.
과도한 리팩토링/새 기능 추가 금지. 요구사항만 구현.
